# Crit 4 Reflection

## 1. What was the breakthrough that moved the work forward?

The breakthrough was realising that making sound was not the same as making an instrument that sounded good.

The first version already worked: I could paint notes, change pitch, and play them with ripples. The automated checks also passed. However, when I actually listened to it, the sounds felt separate and the result was more like scattered noise than music.

I first moved the sounds toward a shared cosmic style, but listening again showed a new problem. Some sounds became too much like sci-fi or game effects. This led to the final dream-pop direction: softer attacks, longer fades, more reverb, and a mix of short and sustained sounds. Even after that, I found the high Bell notes too sharp and adjusted them separately.

The main breakthrough was therefore using listening as part of the development process, not just checking whether the audio code worked.

## 2. What did this work change about who I want to be as a software developer?

This work made me want to be a developer who judges software by how it actually feels to use, not only by whether it passes tests.
Tests were useful for checking the structure and preventing technical problems, but they could not tell me that a sound was too sharp, a loop felt too slow, or the instrument felt like a game instead of music.

I want to keep using technical checks, but also know when human judgement has to become part of the development process. DREAMWASH showed me that correcting a working system can be just as important as building it.
